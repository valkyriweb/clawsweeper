## Findings considered and NOT turned into plans (vetted out — don't re-audit)

The audit fan-out surfaced several alarming claims that were **disproved on inspection**; recorded here so nobody chases them again:

- **"Command injection on untrusted PR content"** — not present. All shell-outs use array-arg `spawnSync`/`execFileSync` (`src/repair/command-runner.ts`, `github-cli.ts`); no `shell: true`, no string interpolation into a shell.
- **"Blindly retries mutations → may have double-merged in production"** — overstated. `shouldRetryGh` (`github-cli.ts`) retries only transient-classified errors, and merges pass `--match-head-commit` (GitHub refuses a second merge) plus `isRecoverableMergeRace` handling in `post-flight.ts`. The genuine residual (non-idempotent **comment** POST) is Plan 004.
- **"execute-fix-artifact / automerge / security-boundary / dashboard worker are untested"** — false. All have tests (`execute-fix-*.test.ts`, `automerge-*.test.ts`, `security-boundary.test.ts`, `dashboard-worker.test.ts`). The real gaps are the merge/finalize **appliers** (`apply-result.ts`, `finalize-open-prs.ts`, `post-flight.ts`, `commit-finding-intake.ts`) — Plan 003 starts on them.
- **"event-record-store has a write race"** — by-design: `event-record-store.ts` uses per-`repo+item` snapshot isolation, and the concurrency model is one worker per item.
- **Dependency lag / abandoned deps** — none: the repo has **zero runtime dependencies** (only dev tooling: `tsgo` preview, `oxlint`, `oxfmt`). The only watch-item is that the toolchain rides previews; already pinned.
- **N+1 at `clawsweeper.ts:3631`** — mislocated citation (that line is plan-sharding logic). No concrete perf finding; real perf work would need profiling under load, not a static guess.
